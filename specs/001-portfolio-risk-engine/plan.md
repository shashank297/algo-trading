# Implementation Plan: Portfolio Risk Engine

**Branch**: `[001-portfolio-risk-engine]` | **Date**: 2026-08-19 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-portfolio-risk-engine/spec.md`

## Summary

Implement a centralized risk management engine that sits between the strategy generation layer and the execution engine. It will validate pre-trade intents against configured max position sizes, portfolio exposures, sector limits, and daily loss thresholds, keeping existing strategies completely unchanged.

## Technical Context

**Language/Version**: Python 3.12+

**Primary Dependencies**: DuckDB (Audit log), Loguru (Logging), Pytest (Validation)

**Storage**: DuckDB (`market_data.duckdb`) - Will require a new `risk_audit_log` table.

**Testing**: Pytest - New test suites required in `tests/test_risk.py`

**Target Platform**: Local execution environments (Windows/Linux)

**Project Type**: Systematic Trading Platform

**Performance Goals**: Low-latency memory evaluation of intents (< 2ms) to support high-throughput event-driven backtesting.

**Constraints**: DuckDB single-writer constraint means audit logs must be batched or written sequentially by the main process thread.

**Scale/Scope**: Intercepting thousands of intents during backtesting without altering strategy source code.

## Constitution Check

*GATE: Passed.* The platform's local-first, deterministic execution nature allows for an isolated `risk/` boundary layer. The implementation will ensure tests remain deterministic and API integrations (Angel One) remain untouched.
